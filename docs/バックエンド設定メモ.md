Spring Boot 開発効率化：DevTools 導入と運用

目的

./gradlew build や手動再起動を不要にし、「コード保存 → 数秒で反映」の開発体験を実現する。

構築手順

1. Spring Boot DevTools の導入

backend/build.gradle の dependencies ブロックに1行追加。

dependencies {
    // 既存の依存...

    // 開発時のみ有効。ファイル変更を検知して自動再起動
    developmentOnly 'org.springframework.boot:spring-boot-devtools'
}


developmentOnly スコープなので本番ビルドには含まれない。

2. OpenAPI 生成タスクの最適化

build.gradle の openApiGenerate 設定に、入力・出力宣言を追加。

openApiGenerate {
    generatorName = 'spring'
    inputSpec     = "$rootDir/../docs/openapi.yaml"
    outputDir     = layout.buildDirectory.dir('generated').get().asFile.absolutePath
    apiPackage    = 'com.example.api'
    modelPackage  = 'com.example.api.model'
    configOptions = [
        interfaceOnly   : 'true',
        useSpringBoot3  : 'true',
        useTags         : 'true',
        dateLibrary     : 'java8',
        openApiNullable : 'false',
    ]

    // ↓ここを追加
    inputs.file("$rootDir/../docs/openapi.yaml")
    outputs.dir(layout.buildDirectory.dir('generated'))
}


これで openapi.yaml が変更されていない限り、openApiGenerate タスクはスキップされる（Gradleのup-to-dateチェックが効く）。

3. IntelliJ IDEA 設定

DevTools を効かせるには IntelliJ 側の自動ビルド設定が必要。

Settings（Preferences）→ Build, Execution, Deployment → Compiler

	•	✅ Build project automatically

Settings → Advanced Settings

	•	✅ Allow auto-make to start even if developed application is currently running

この2つをONにすることで、ファイル保存時に自動コンパイル → DevTools が検知して再起動、という流れが成立する。

運用方法

日々の開発フロー

# 1. DB起動（一度起動したら一日触らない）
docker compose up -d

# 2. バックエンド起動（一度起動したら一日触らない）
cd backend
./gradlew bootRun

# 3. フロントエンド起動（別ターミナル、一度起動したら一日触らない）
npm run dev


コード変更時の挙動

|操作                    |結果                                     |
|----------------------|---------------------------------------|
|Javaコードを保存            |IntelliJが自動コンパイル → DevToolsが検知 → 数秒で再起動|
|`openapi.yaml` を編集して保存|次のビルド時のみ `openApiGenerate` が走る         |
|フロントのコードを保存           |Vite HMR で即座にブラウザ反映                    |

手動で ./gradlew build を叩くタイミング

普段は不要。以下の場合のみ：

	•	依存ライブラリを追加・変更したとき
	•	CIに通す前の最終確認
	•	ビルド成果物（jar）が必要なとき

openapi.yaml を変更したとき

# バックエンド：次回ビルド/起動時に自動で再生成される
# （手動で走らせたい場合のみ）
cd backend && ./gradlew openApiGenerate

# フロントエンド：手動で型再生成
npm run gen:types


トラブルシュート

DevToolsが効かない場合のチェックリスト

	1.	IntelliJの「Build project automatically」がONか
	2.	「Allow auto-make to start even if developed application is currently running」がONか
	3.	developmentOnly スコープで依存が入っているか（implementation ではダメ）
	4.	./gradlew bootRun で起動しているか（jar直接実行ではDevToolsが効かない場合あり）

再起動が遅い・走らない場合

	•	IntelliJ で対象ファイルを保存した後、Ctrl + F9（Build → Build Project）で手動コンパイルを試す
	•	ログに Restarting due to ... が出るか確認

補足：なぜこの構成にするか

	•	DevTools はクラスローダーを2つに分けることで、フルJVM再起動より高速にアプリだけ再起動する仕組み
	•	Gradle の up-to-date チェック は inputs/outputs を宣言したタスクで自動的に働く。入力ファイルのハッシュが変わらなければスキップ
	•	Docker は DB のみ に留めることで、IntelliJ のコード補完・デバッガ・ホットリロードを最大限活用できる
